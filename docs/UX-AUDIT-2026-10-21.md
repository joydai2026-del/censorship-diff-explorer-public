# Hands-on UX audit, 2026-10-21

I used the app as a first-time researcher would: the web page at desktop (1440x900), iPhone 15 and Pixel 7
sizes (headless Chromium with the device profiles), and the command line, using the repo's sample snapshots
plus my own small files (two good files, one empty, one broken JSON, one with no time zone, one wrong shape,
duplicates, and 20 files of about 5,000 posts each, 11 MB).

Every count was checked by hand against the sample files with a separate script (plain set difference of post
ids between consecutive captures). Hand result: Sep 2: 1, Sep 3: 2, Sep 4: 4 (s010 came back later),
Sep 5: 2, Sep 6: 7 (3 from the 00:20 Beijing capture, 4 from 09:00), Sep 7: broken capture ignored, Sep 8: 3.
Total 19 of 30 posts. The page and the CLI show exactly this.

Screenshots and transcripts: `evidence/ux-audit-2026-10-21/` (`-after` = re-test after the fix). Raw step logs:
`audit-log-before.json`, `audit-log-after.json`. D = desktop, I = iPhone 15, P = Pixel 7.

**Result: 45 functions tested. 35 work, 4 broken (all fixed), 6 confusing (5 fixed), 4 not testable.**

## Not testable and why

| Function | Why |
|---|---|
| Drag and drop of files | Not built. The page has only a file picker. (In most browsers, dropping a file on a page that does not handle drops opens the file instead, which would leave the page; not verified here.) |
| Sorting | Not built. Posts are always in deletion order. |
| Export / download of results | Not built in the page. The CLI `--out` covers it for scripts. |
| Links to original posts | Not built, and the sample data has no post URLs. |

## Suggestions for Rowan (product or design choices, not changed)

1. Move "Use your own snapshot files" higher, or open it by default when no sample banner is shown. A first-time journalist may not scroll to the bottom to find it.
2. Accept drag and drop onto the page, and stop a dropped file from replacing the page.
3. Add "Download these results (CSV/JSON)" so a journalist can take the filtered list away.
4. Make day picks real browser history steps so Back returns to the previous day instead of leaving the page.
5. Warn when two files have the same capture time (likely the same file picked twice).
6. Say on the page that your own files are not kept after a refresh.
7. Optional sort (by deletion date, time online, account) and a link field for the original post URL, if real scrapers provide one.
